# Dual workspace: comfortable alpha candidate

This separate source experiment responds to the user's implementation feedback: “左侧无透明度，右侧太紧凑，无设计感，不圆滑”. The accepted v2 dual structure remains. Earlier candidates/packages stay available; this does not replace the stable production or v2 review entry.

`MaterialWindow` uses Qt's documented Windows translucent-widget route: top-level `WA_TranslucentBackground` and `FramelessWindowHint` before first show, transparent root, real per-pixel sidebar/title-bar alpha, and fully opaque content. Whole-window opacity stays at its default 1.0. Dark sidebar alpha is 184/255, light is 208/255. Text/buttons retain their own opaque colors. The tint is actual alpha, **not backdrop blur**. There is no wallpaper/desktop screenshot, simulated background image, DWM request, undocumented composition API, installation or settings write in this candidate.

A read-only accessibility query and the existing Windows EnableTransparency preference select opaque fallback. The app also provides an explicit sidebar-transparent toggle. Deactivation uses opaque tint; activation restores the user's candidate choice. Unsupported platforms fall back. Maximization removes outer corner radii; regular-window corners and stage corners are antialiased painting, not hard region masks.

The default window is 1360×920. Navigation is 200 DIP; observation/properties are approximately 42:58 with a thin divider. Property groups have 20 DIP spacing, 16 DIP radii, inner padding and 86/76 DIP family/palette specimens. Grouped rows are at least 52 DIP, common controls 38–40 DIP. Properties scroll rather than shrinking all items into the first viewport. Settings uses matching groups. Apply is fixed at 64 DIP. At 880 px palette becomes two columns; modest outer-margin/gap adaptation preserves the right panel's controls. The fixed left observation adjusts its stage height for low windows while containing the entire original 64 px cursor canvas; a redundant role heading disappears there, while five common roles and the complete selector remain.

The title bar has accessible minimize/maximize-restore/close buttons and double-click maximize. Real mouse handlers call `QWindow.startSystemMove()` and `startSystemResize()` and retain their boolean return values. Eight edge/corner zones show resize cursors. Alt+Space opens an app-owned command menu; keyboard move/resize support arrow keys, Enter commit and Escape restore. Alt+F4 uses the existing close/dirty-confirmation path. **Native hover Snap flyout is not implemented**: no undocumented/native hit-test trick is added. Real drag/resize, Windows keyboard Snap, mixed-DPI movement and desktop composition remain manual review items; the Qt dispatch/state tests do not prove these physical desktop behaviors.

The Windows own-window probe used `WA_ShowWithoutActivating`, exposed only this created window, recorded an 8-bit native alpha buffer and closed only its own instance. Widget captures prove application alpha pixels, not the composited desktop behind them. No supported desktop-observation tool is available here, so final visible transparency/blur must not be claimed as accepted. Pure alpha can now be tried in the isolated candidate; Acrylic is not silently conflated with it. Prior type-2 Mica acceptance was an opaque wallpaper-derived material capability probe, not a transparent-client success.

Official references: [Qt 6.11 QWidget translucent windows](https://doc.qt.io/qt-6.11/qwidget.html#creating-translucent-windows), [Qt 6.11 QWindow system move/resize](https://doc.qt.io/qt-6.11/qwindow.html#startSystemMove), [Qt shaped-clock example](https://doc.qt.io/qt-6.11/qtwidgets-widgets-shapedclock-example.html), [DWM backdrop types](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type), [Windows hover Snap requirement](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/apply-snap-layout-menu).

Safe source entry: `.local/SAFE-Pointer-Material-v2-Preview.cmd`. It constructs Mock settings with tray/update disabled; all cursor/startup backend actions reject, and updater callbacks/services are isolated. No saved user settings are loaded or persisted. Renderer, original resources, restored motion/clock, historical shapes, retired effects, draft/immediate semantics and owned confirmation colors are reused. This is a review candidate, not a new packaged build or publication. Evidence is private in `.local/material-v2/`: actual Qt two-page/theme/size/custom captures, native probe, tests, preservation report and SHA256 manifest. Final counts and remaining review items are in its delivery.json.
