# Pointer 桌面应用设计

日期：2026-10-03。开发分支：`DEV`。状态：供用户审阅，尚未开始产品代码实现。

## 目标与已确认偏好

用户希望从 GitHub 下载安装包，在 APP 内自定义光标属性，并将现有测试网页移植到 APP。用户选择优先精致界面，可以接受更大的安装包。

首版交付 Windows x64 桌面应用、可升级和卸载的安装 EXE、便携启动 ZIP、校验文件及 GitHub 下载入口。保持现有圆角光标风格、深浅背景自适应和左键动效。所有开发提交推送 DEV。

## 技术与体积

- 界面采用 PySide6-Essentials 的 Qt Widgets；只使用 QtCore、QtGui、QtWidgets，不依赖 WebEngine 或本地 HTTP 服务。
- 沿用 Python 3.13、Pillow 光标绘制和 PyInstaller 打包；安装程序采用 Inno Setup。
- 设置界面与后台光标服务是独立进程。`--run` 延迟加载 GUI 模块，关闭设置窗口会退出 GUI 进程，后台服务继续工作。
- 目标是压缩安装包不超过约 50 MiB；最终报告实际大小及 GUI/后台内存和空闲 CPU，超出目标时先精简依赖再报告原因。
- 用户安装后无需安装 Python 或 Qt；配置、预览、应用和测试均可离线使用。

## 界面与用户流程

默认窗口约 1100×760，支持窗口缩放、高 DPI、中文字体和键盘导航。使用石墨色侧栏、浅色内容面板、克制的强调色和圆角卡片。中文文案解释效果，不向普通用户暴露运行命令和注册表路径。

侧栏包含“光标外观”“左键动效”“光标测试”“应用设置”。底部显示运行状态及版本。

外观页和动效页右侧保留深浅背景预览，切换箭头、小手、输入和加载状态。修改只影响草稿与预览；“应用配置”才改变系统设置。显示未应用状态，提供放弃修改。应用在工作线程进行，界面保持响应；失败时提示具体原因，并保留原来可用配置。

首次打开展示当前状态与预览，用户应用后启用 Pointer。升级已有用户保留现有配置和开机启动选择，不自动覆盖原光标备份。

关闭窗口退出设置界面，不停止后台服务。“暂停光标效果”与“开机启动”互相独立；“恢复 Windows 原光标”停止后台并取消 Pointer 启动项，保留用户自定义配置供以后恢复使用。

## 首版可配置属性

| 属性 | 范围与行为 | 初始值 |
| --- | --- | --- |
| 配色策略 | 自动适应、固定浅色背景方案、固定深色背景方案 | 自动适应 |
| 两套配色 | 分别设置主体与边框颜色，使用原生颜色选择器；显示对比度预览 | 浅背景黑主体白边框；深背景白主体黑边框 |
| 光标大小 | 24、32、40、48、64，作为逻辑尺寸随 DPI 缩放 | 32 |
| 左键动效 | 整体倾斜、缩小回弹、关闭 | 倾斜；升级优先保留旧选择 |
| 动效强度 | 0–100%；50% 对应现有箭头 6°、小手 12°，缩小 10%；100% 对应箭头 12°、小手 24°，缩小 20% | 50% |
| 按下时间 | 40–200 ms | 60 ms |
| 松开时间 | 80–400 ms | 150 ms |
| 开机启动 | 用户明确开关，仅值改变时更新启动项 | 新安装默认关闭；升级保持实际状态 |

大小和配色覆盖现有全部系统光标角色；点击动效只作用于普通箭头和链接小手。箭头保持整体形状，顶部向左下倾斜明显，下方两尖轻微跟随。输入光标与加载动画保持当前造型。

提供“恢复默认配置”、JSON 导入与导出。导出只包含用户设置和格式版本，不包含机器路径、系统备份、启动项或进程信息。导入先完整校验再更新草稿，不立即修改系统。

## APP 内光标测试

使用 Qt 原生控件重建原网页交互，无需浏览器组件。保留旧网页作为额外开发测试工具。

- **深浅适配**：亮度滑块、黑白交界面、不同灰度色块；显示当前后台识别的方案。
- **左键动效**：深浅两块空白区域测试箭头；按钮测试小手；显示按下、松开、长按状态和点击计数。
- **文字输入**：可编辑文字框，验证 I 形光标。
- **链接与拖动**：系统小手区域、可拖动卡片和拖动过程反馈。
- **加载状态**：仅在指定测试区域显示 Windows 等待或后台忙碌光标；明确开始和结束，不锁定整个 APP。
- **其他角色**：禁用、移动、水平/垂直/对角缩放等已有角色测试区域。

测试区域使用 Windows 原生共享系统光标句柄，由现有服务更新显示；避免 Qt 私有复制光标导致无法反映系统动效。不得绘制跟随鼠标的替身冒充系统光标。

预览与测试是不同功能：预览呈现未应用的草稿；测试页观察当前实际应用的系统光标。点击计数只证明接收了事件，不宣称已自动验证肉眼可见的动效。

## 配置与资源架构

用户追加要求：制作 APP 时同步重构文件架构，清晰、简洁。最终目录按功能组织，界面只调用 application，不直接操作注册表；光标配置与绘图可以独立测试。移除重复实现，不长期保留整套新旧模块。

```text
src/pointer/
  __main__.py, cli.py, paths.py, application.py
  cursor/
    settings.py, motion.py, resources.py
    art/                  # arrow、hand、roles、palette、animation、codec
  windows/
    api.py, scheme.py, startup.py, engine.py, installation.py
  ui/
    main_window.py, preview.py, theme.py, workers.py
    pages/                # appearance、motion、tests、preferences
assets/cursors/           # adaptive 与 reference 默认资源
packaging/windows/        # 入口、安装脚本、图标与用户说明
requirements/             # runtime、build、dev 依赖
scripts/                  # 构建、默认资源生成、开发测试页启动
web/cursor-test/          # 保留原网页，作为额外开发测试工具
tests/
  unit/                   # cursor、windows、ui
  integration/            # 原生光标、升级与打包验证
docs/
  design/                 # 设计文档
  plans/                  # 实施计划
  architecture.md, usage.txt
.github/workflows/        # 测试与发布
```

`cursor/settings.py` 负责纯数据模型、校验、原子存储、迁移和导入导出；`cursor/art` 是预览和系统资源共用的唯一绘图实现；`cursor/resources.py` 准备并校验缓存。`windows` 封装 Windows API、注册表方案、启动项、后台引擎和安装文件生命周期。`application.py` 编排应用、暂停、恢复和升级事务。`ui` 管理草稿和反馈，`cli.py` 保留原有显式命令入口。

先重构现有能力并跑通现有测试，再添加界面；旧生成工具收敛成 scripts 中的单一入口。现有 CUR/ANI 与造型保持兼容，所有引用、工作流、包清单和 README 同步更新。测试使用逐层 discover 支持的包结构，任何旧测试都不得因移动而悄悄漏跑。

用户数据仍放在用户目录下的 `Pointer/data`，与安装程序文件隔离。新增版本化 `settings.json`；首次迁移从 `click-motion-settings.json` 读取旧动效选择，缺失时采用默认值。迁移不修改原光标和启动项备份。

绘图在配置应用或预览变化时发生，后台按下循环不绘图、不读配置文件、不访问网络。新资源生成到临时目录，验证完整性后发布；只清理本 APP 已验证拥有的旧缓存。

所有动效帧保留一致的点击热点。旋转和缩放预留透明边距，在最大强度、全部支持大小和 DPI 下不裁切。设置界面使用同一绘制实现预览，避免预览与实际资源形状不同。

应用事务：校验草稿 → 准备并检查新资源 → 停止旧服务 → 保存配置并加载新光标 → 启动服务 → 确认就绪。任一步失败，恢复旧配置和旧光标；恢复过程也失败时明确报告，不错误显示“已应用”。

开机启动是独立配置，不因应用配色、大小或动效而启用、关闭、删除或重建。GUI 单实例，重复启动聚焦现有窗口；后台仍使用原有互斥量和停止事件。

## 安装、升级与 GitHub 下载

安装 EXE 按当前用户安装，无需管理员权限，创建开始菜单入口和卸载入口。可选择桌面快捷方式与安装完成后启动 APP。安装过程不隐式启用开机启动。

升级在覆盖文件前让旧 GUI 与后台服务正常退出，保留设置、生成资源和最初 Windows 光标备份；完成后按升级前运行状态恢复。失败时返回明确错误，不继续展示安装成功。

卸载在删除程序文件前恢复原系统光标并取消本 APP 开机启动。恢复失败时中止卸载以保留恢复所需文件。仅删除清单拥有的程序文件；用户设置默认保留，提供明确的可选清除项。

ZIP 双击 `Pointer.exe` 打开界面，可直接预览。首次应用时将持久光标资源和运行文件部署到用户目录，保证解压目录移动或删除后不破坏系统方案。旧的显式命令入口保留兼容；无参数启动改为设置界面。

在 GitHub 提供安装 EXE、ZIP、各自 SHA-256 和中文发布说明；先发布从 DEV 构建的桌面预览版，不将 DEV 合并 main，不替换当前稳定版下载入口。此请求授权提供 GitHub 可下载的 APP 安装包。发布版本、标签与清单一致，正式发布前完成安装和卸载验证。

## 验证与交付标准

1. 配置边界、无效颜色/数值/JSON、未知格式版本、损坏配置、迁移和导入失败不破坏旧设置。
2. 默认造型兼容；最大强度和全部支持大小的深浅资源无裁切；每档热点一致；ANI 保留真实多帧。
3. 所有 GUI 控件连接实际配置或操作，应用失败反馈、未应用状态、导入导出、重开窗口和重复启动可验证。
4. APP 内各测试区域使用真实 Windows 光标；离开等待测试后恢复正确角色；拖动、失焦和快速连点不会卡在按下状态。
5. 停止、恢复、应用、升级均保持备份完整；未改变的启动项不得重写；后台退出 GUI 后继续运行。
6. 在实际 Windows 上验证安装、升级、重启界面、启动项开关、恢复与卸载；使用测试安装目录保护当前用户原始备份。
7. GitHub Actions 运行单元测试、GUI 离屏检查、资源诊断及安装包校验；本地检查真实 DPI 显示和关键交互。
8. 交付 APP 界面截图、安装包链接、实测体积与资源占用，以及明确的验证限制。
